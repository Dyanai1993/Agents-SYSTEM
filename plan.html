Multi-Agent Engineering System — Phase 0 plan

Date: 2026-11-03. No system code exists yet. Challenge every number. A number marked "(assumption)" is a guess.

Result when all phases are done
  • You type one task in plain language. A fixed state machine runs 3 core agents in sequence: Architect, Developer, Tester.
  • Every run uses your Max login. The billing guard stops the run if an API key exists.
  • You approve merge, deploy, delete and send actions in a local dashboard. The dashboard never calls an LLM.
  • The system learns only through lessons that you approve and that pass the evals.

Important billing finding. Your premise is correct today: SDK and claude -p with a plan login use subscription limits. But since 2026-10-07 Max also gives monthly API credits. These work only with an API key. The plan ignores them, as you require. See step 1.

Important location finding. This repo (investment-os) is an unrelated app. The plan puts the system in agent-system/. See decision D8.

3. A plain script, not an LLM, moves each task through 9 main states and 3 end states.
  • State lives in tasks/<id>/state.json. Each step writes it first. A killed run resumes from it.
  • The LLM part does only intake and routing doubts. All transitions are code.
  • Skipped states (for example no integration) are marked skipped, not removed.

5. Each task stops at 3 fix loops, 2 re-plans, 40 agent calls (assumption) or 45 minutes (assumption).

  "by_model": {"sonnet": 9, "haiku": 2, "opus": 0},
  "limit_hits": [] }
  • The SDK result message gives real token counts per call. The ledger sums them.
  • A limit error from the SDK or CLI is the ground truth. The system saves state and stops. It never retries in a tight loop.
  • A task whose estimate is above the remaining window does not start. The system asks you.
  • Results cache by input hash. Unchanged research, scans and tests do not run again.
  • Weak point: there is no official remaining-window number. The estimate can be wrong. Phase 1 calibrates it from real limit hits.
